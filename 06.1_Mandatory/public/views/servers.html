What is a Rest API?

Rest API conventions

First thing first, we'll need to understand the three HTTP conventions. The conventions are as follows:

  • Using the correct HTTP verb (GET, POST, PUT, PATCH, DELETE)
  • Using the correct order, as shown in the table below.
  • Using the correct naming conventions. It has to be a noun and it has to be in plural.

Let's create an example for a website with flags.

HTTP Method Endpoint Description
GET /flags Retrieves all flags
GET /flags/:id Retrieves a specific flag by id
POST /flags Creates a flag resource
PUT /flags/:id Replaces an entire flag resource
PATCH /flags/:id Replaces parts of the flag resource
DELETE /flags/:id Deletes a flag ressource.

Let's look at the order of it. We'll start with a GET, this makes a lot of sense, since we'll start out
with retrieving information, often some kind of frontpage which retrieves a html file.
The next method is also GET, once again we're retrieving information, this time from a specific id.
We then have POST, which makes sense to have after the GET methods, as we'll need to retrieve something before we can
add our own addition, such as adding a new flag to a list.
PUT and PATCH are the next 2 methods.
It is worth noting that the PUT method, is rarely used, as it is rarely necessary to edit an entire resource. Keep in mind that PUT also gives the resource a new ID.
without simply deleting and creating a new resource. If editing a resource it makes more sense to use PATCH.
Again, however, it makes sense to have these methods after POST, as you'll need a resource to edit.
And last, but not least, we have DELETE which makes perfect sense to be the very last method, as this is the one to remove the resource.
Note that every endpoint uses flags in plural instead of flag in singular.
This is part of the naming convention, as mentioned earlier.
Notice how in node.js we use /:id. In Java I am used to using /{id}, but the pathvariable is a slightly different syntax in node.js

Client/Server and app.js

Client sends a request (shortened to req), server sends a response (shortened to res). Use res.send(); to send a response back to the client. We use a generic data-type to send data. 


      app.get('/', (req, res) => {
        res.send({ data: "Hello, how are you?" });
      });

The example above is called a route. '/' is the endpoint, it could also have been '/flags' for example. (req, res) => {} is a an example of a callback function. Learn more about callback functions here res.send() sends a JavaScript object, which is parsed into json by the help of express. Without res.send(), the browser will load forever.

Misc

To parse JSON, you must first enable the express JSON-parser like so:


      app.use(express.json());

app.listen() must always be at the bottom of the app.js file.


      const PORT = 8080;
        app.listen(PORT, (error) => {
            if (error) {
                console.log("There was an error starting the server", error);
            }
            console.log("Server is running on port", PORT);
        });
