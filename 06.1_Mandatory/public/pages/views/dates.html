Date()

The Date object makes it possible to code with dates.

Current date and time

Date()
// output will be a String such as "Sat Oct 10 2026 11:54:54 GMT+0200 (Central European Summer Time)"
  
Date.now()
// output will be something like: 1790940898647

Date() gives you a String with the current time and timezone for where the code is running.

Date.now() will give you the current time in Unix Epoch Time. The epoch started on January 1st 1970 at midnight UTC.

new Date()

When using new Date() without any parameters it will give the current local time.

While Date() and Date.now() return a String and a Number, new Date() returns an object, so you can call methods on it. 

new Date();
// output will be an object, shown as "Sat Oct 10 2026 11:54:54 GMT+0200 (Central European Summer Time)"

new Date(2026, 0, 1);
// output will be an object, shown as "Thu Jan 01 2026 00:00:00 GMT+0100 (Central European Standard Time)"

You might notice the 2 different timezones, which is due to the first example being in summer time, while the second example is in winter time.

Another thing to pick up on, is the date in the second example. Here the 0 represents January. This is because it is indexed at 0.

Date.parse()

The standard format for date and time is ISO 8601. That would be YYYY-MM-DD for dates and HH:mm:ss for time. Or the combined YYYY-MM-DDTHH:mm:ss, where date and time is separated with a T. 

Date.parse("1970-01-01");
// This exact example gives 0 as output

Date.parse("2026-01-01");
// Gives 1767225600000 as output

Date.parse() takes a date String and gives you the number of milliseconds since the Unix Epoch time. Since the epoch started on January 1st 1970, the first example equals 0. The second example gives a much higher number - 56 years in milliseconds.

Instance methods

The Date object has a lot of instance methods, but some of the more popular ones are: 

const birthday = new Date("2026-10-02");

birthday.getDate();
// output is 2, getDate() gives the date.

birthday.getDay();
// output is 5 (Friday)
// Sunday -> Saturday is indexed 0 - 6

birthday.getFullYear();
// output is 2026

Formatting dates

birthday.toLocaleDateString();
// output is 2.10.2026 if located in Denmark.

birthday.toLocaleDateString("en-uk");
// output is 2/10/2026. en-uk is the British standard. The Danish standard is da-dk.

const options = {
  weekday: "long",
  year: "numeric",
  month: "long",
  day: "numeric",
};

birthday.toLocaleDateString("en-uk", options);
// output is Friday, 2 October 2026

Understanding timezones

It is important to understand the timezones for the Date object, as it can cause major bugs without proper understanding. 

Date.parse("1970-01-01");
// The output here would be 0

new Date(1970, 0, 1).getTime();
// The output here would be -3600000 in my local timezone

This can seem confusing, since it's the exact same date. This is because a Date String like "1970-01-01" is read in UTC, while the numbered date is read in local time.

Since the new Date(1970, 0, 1) example is read in local time, and my local time is UTC+1 in winter and UTC+2 in summer, it is giving us the milliseconds from the epoch to January 1st 1970 at 00:00 in my local timezone, which equals -3600000, as it was December 31st 1969 at 23:00, 1 hour before the epoch.
