SSR

DRY (Don't Repeat Yourself) code is a general guideline when it comes to programming. The less your code repeats itself, the more reusable it is, and the less you'll have to fix every time you make a change.

When it comes to SSR (Server Side Rendering) you will split up your HTML files, into sections that are repetitive. This will often be the header and the footer, but it can be other things such as a navigation bar.

Splitting up the HTML page

You simply create a header.html and a footer.html, to put the content that all your HTML pages need, in those files.

Your header.html might look something like this:

<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <link rel="stylesheet" href="/assets/css/index.css" />

    <title>Document</title>
  </head>
  <body>
  <main>

And your footer.html might look something like this:

</main>

    <footer>© 2026</footer>
  </body>
</html>

Templating Engine

While it is possible to install templating engines, it is nice to create your own so you have full control of the content.

The first thing you'll want to do, is create a function that can read your HTML files. 

import fs from "fs";
  
export function readPage(path) {
  return fs.readFileSync(path, "utf-8");
}

We have an import from 'fs', which is a part of the node library. It stands for File System, and is needed to read files.

The function above, simply reads a HTML file. It takes a path and utf-8 as an argument. You could also make it: 

return fs.readFileSync(path).toString();

And it would be the same outcome.

The next step would be to create a function that can construct the page with header, content and footer. 

export function constructPage(page) {
  const header = readPage("public/components/header/header.html");
  const footer = readPage("public/components/footer/footer.html");

return header + page + footer;
}

The function takes a page as a parameter. It saves header.html and footer.html in a variable, and then constructs the page by returning the header + page + footer, resulting in a full HTML page.

It is needed to export the function, because we use it in another .js file.

Right now, every page gets the same tab title, and dosn't have the ability for unique styling or other unique features. This can be solved, by expanding the function. 

export function constructPage(page, options = {}) {
  const header = readPage("public/components/header/header.html");
  const footer = readPage("public/components/footer/footer.html");

  return (
    header
      .replace("{{CSS_LINKS}}", options.cssLink || "")
      .replace("{{TAB_TITLE}}", options.tabTitle || "Flags")
    + page
    + footer
  );
}

The function is using a default parameter, so each page can have unique features, such as a unique css link or tab title. The .replace method replaces the placeholder with the value.

In the HTML file, it might look like this for example in the header.html:

<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <link rel="stylesheet" href="/assets/css/index.css" />
    {{CSS_LINKS}}

    <title>{{TAB_TITLE}}</title>
  </head>
  <body>
  <main>

pages.js

import { readPage, constructPage } from "./templatingEngine.js";

const frontpage = readPage("public/pages/frontpage/frontpage.html");
const about = readPage("public/pages/about/about.html");

export const frontpagePage = constructPage(frontpage)

export const aboutPage = constructPage(about, {
  tabTitle: "Flags | About"
});

We import the readPage and constructPage functions that we created earlier. We save each HTML file in a variable, and export them with their unique features.

app.js

import { frontpagePage, aboutPage } from "./templatingEngine/pages.js";

app.get("/", (req, res) => {
  res.send(frontpagePage);
});

app.get("/about", (req, res) => {
  res.send(aboutPage);
});

The finished pages are imported from pages.js, and each route sends the finished page to the browser.
