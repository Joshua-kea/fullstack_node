Introduction to starting a server

Rest API conventions

First thing first, we'll need to understand the three HTTP conventions. The conventions are as follows:

  • Using the correct HTTP verb (GET, POST, PUT, PATCH, DELETE)
  • Using the correct order, as shown in the table below.
  • Using the correct naming conventions. It has to be a noun and it has to be in plural.

Let's create an example for a website with flags.

HTTP Method Endpoint Description
GET /flags Retrieves all flags
GET /flags/:id Retrieves a specific flag by id
POST /flags Creates a flag resource
PUT /flags/:id Replaces an entire flag resource
PATCH /flags/:id Replaces parts of the flag resource
DELETE /flags/:id Deletes a flag resource.

Let's look at the order of it. We'll start with a GET, this makes a lot of sense, since we'll start out with retrieving information, often some kind of frontpage which retrieves a html file.

The next method is also GET, once again we're retrieving information, this time from a specific id.

We then have POST, which makes sense to have after the GET methods, as we'll need to retrieve something before we can add our own addition, such as adding a new flag to a list.

PUT and PATCH are the next 2 methods. It is worth noting that the PUT method, is rarely used, as it is rarely necessary to edit an entire resource.

Keep in mind that PUT also gives the resource a new ID. without simply deleting and creating a new resource. If editing a resource it makes more sense to use PATCH. Again, however, it makes sense to have these methods after POST, as you'll need a resource to edit.

And last, but not least, we have DELETE which makes perfect sense to be the very last method, as this is the one to remove the resource.

Note that every endpoint uses flags in plural instead of flag in singular. This is part of the naming convention, as mentioned earlier. Notice how in Node.js we use /:id. In Java I am used to using /{id}, but the pathvariable is a slightly different syntax in Node.js

Client/Server and app.js

Client sends a request (shortened to req), server sends a response (shortened to res). Use res.send(); to send a response back to the client. We use a generic data-type to send data. 

app.get('/', (req, res) => {
  res.send({ data: "Hello, how are you?" });
});

The example above is called a route. '/' is the endpoint, it could also have been '/flags' for example. (req, res) => {} is a an example of a callback function. Learn more about callback functions here res.send() sends a JavaScript object, which is parsed into json by the help of express. Without res.send(), the browser will load forever.

app.js

Delete method example:

app.delete("/flags/:id", (req, res) => {
const providedId = Number(req.params.id);
const foundFlagIndex = flags.findIndex(
  (flag) => flag.id === providedId,
);

if (foundFlagIndex === -1) {
  return res.status(404).send({ errorMessage: `No flag found by id ${providedId}` });
}
        
flags.splice(foundFlagIndex, 1);        
  res.status(204).send();
})

Patch method example:

app.patch('/flags/:id', (req, res) => {
  const providedId = Number(req.params.id);
  const foundFlagIndex = flags.findIndex(
    (flag) => flag.id === providedId,
  );

  if (foundFlagIndex === -1) {
    return res.status(404).send({ errorMessage: `No flag found by id ${providedId}`});
  }
        
  const providedFlag = req.body;
  const foundFlag = flags[foundFlagIndex];

  const flagToCreate = {...foundFlag, ...providedFlag, id: providedId };

  flags[foundFlagIndex] = flagToCreate;

  res.send({ data: flagToCreate });
});

In a patch method it is important to put id: providedId at the end, to make sure the id isn't lost in the process. If you put it as the first thing, it might not stay the same id.

Post method example:

app.post('/flags', (req, res) => {
  const providedFlag = req.body;

  providedFlag.id = nextId++;

  flags.push(providedFlag);

  res.send({ data: providedFlag });
});

app.listen() must always be at the bottom of the app.js file.

const PORT = 8080;
  app.listen(PORT, (error) => {
    if (error) {
      console.log("There was an error starting the server", error);
    }
  console.log("Server is running on port", PORT);
});

Fetch

app.get("/proxy", (req, res) => {
  fetch("https://www.google.com")
    .then((response) => response.text())
    .then((result) => res.send(result));  
});

In this example we're fetching Google.com, to create a proxy of Google.com. Google is text HTML, which is why we use .text() instead of .json(). The result is the HTML page.

If your browser settings is in a language with non-English symbols, you might get a weird looking website. A way to solve that, is by using arrayBuffer() and TextDecoder(). 

app.get("/proxy", (req, res) => {
  fetch("https://www.google.com")
    .then((response) => response.arrayBuffer())
    .then((buffer) => {
      const decoder = new TextDecoder("ISO-8859-1");
      const text = decoder.decoder(buffer);
      res.send();
    })
});

This example is set to the Danish standard, so the website can show Danish symbols.

Parsing JSON with Express

To parse JSON, you must first enable the express JSON-parser like so:

app.use(express.json());

It has to be right under your imports at the top of the file.

Query String

http://localhost:8080/bars/forgottenItems?wallet=200&keys=my_house&my_baby=Sam

The end of the URL ('forgottenItems?wallet=200&keys=my_house&my_baby=Sam') above is called the query string, which is a way to save information.

dirname

To avoid putting your exact path name, with your personal folders, in the program you should instead use __dirname. 

app.get('/', (req, res) => {
  res.sendFile(__dirname + '/index.html');
});

Example of usage

If we say there is a folder called Flags_Project which has a file called app.js inside, we could do the following: 

cd Flags_Project
node app.js

This would run app.js, but whenever a change is made in the file, it is needed to stop the server with ^C and run it again.

Luckily there is a faster way to run the server.

cd Flags_Project
nodemon app.js

The command "cd Flags_Project" is simply to change directory to the specific folder, and is only needed to be done if you're not actively in the correct directory.

The important part of the above command is nodemon, which makes it possible to run the server without having to constantly re-run it.

Note that nodemon needs to be installed to work. Install nodemon from npm 

npm install -g nodemon
